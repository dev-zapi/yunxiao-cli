# Flow 查询命令结构

## 背景

Flow OpenAPI 的查询接口分散在流水线、运行任务、部署、主机组、资源成员、
服务连接、标签和变量组等资源边界。原有 CLI 已提供流水线运行和服务连接的
基础命令，但无法覆盖这些资源的只读查询。

## 决策

查询接口按资源分组为 `pipelines`、`jobs`、`deploy`、`host-groups`、
`pipeline-groups`、`resource-members`、`connections`、`tags` 和
`variable-groups`。现有命令保持兼容；新增接口使用资源导向的子命令和字符串
形式的 ID、过滤器及未公开枚举。

查询命令统一发送一次请求并输出 API 原始响应。CLI 不自动翻页、下载制品、
跟随 URL、脱敏字段或推断未公开枚举；分页和敏感数据处理由调用方根据组织
策略决定。

## 替代方案

- 按 OpenAPI 操作名直接暴露几十个顶层命令。
- 在 CLI 中封装自动分页、URL 下载和响应字段规范化。
- 为服务连接、关系类型等文档不完整的字段硬编码本地枚举。

这些方案会放大命令表面、隐藏 API 响应语义，或在云效版本和组织配置变化时
造成 CLI 先于服务失效，因此不采用。

## 后果

Agent 可以按资源边界发现查询入口，并通过 `--output json` 组合后续处理；
同时，调用方需要自行处理分页、URL 生命周期、敏感字段和类型值的有效性。
查询手册中的示例值仅作参考，不能视为稳定枚举。
