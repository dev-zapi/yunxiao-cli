# 云效使用反馈收集

在问题发生的会话里，把 yunxiao CLI 及其技能的使用问题梳理成可分诊的报告文件。

**本技能只做收集，不做修复**：不改代码、不开 issue、不改技能文档、不汇总收割。消费这些报告是人的事——收集阶段的过度介入（顺手修复、猜测修复方案）会让报告失去"问题现场记录"的价值。

## 何时使用 / 不要使用

**使用**：用户明确要求记录、收集、留存云效使用问题或反馈（说法不限，"记下来""收集一下""这个问题得让他们改"都算）。

**不要使用**：用户正在遭遇报错、要求解决眼前问题——此时先帮忙排障。收集动作的触发权永远在用户手上：自动触发会在用户专心干活时打断流程，还会制造没人消费的噪音报告。

## 核心流程

### 1. 确定信息源

默认是**当前会话的上下文**：回看本会话中 yunxiao 相关的命令调用、输出、报错和用户的抱怨。

如果用户给了**历史会话转录文件路径**（形如 `~/.claude/projects/<proj>/<session>.jsonl`），从该文件提取：

- 每行一个 JSON 对象，`.type` 为 `user`/`assistant`，`.message.content` 是字符串或数组（数组元素带 `type`：`text`、`tool_use`、`tool_result`）
- 用 grep/jq 定位包含 `yunxiao` 的 `tool_use` 命令和 `is_error` 的 `tool_result`
- 只处理用户指定的这一个文件，不要顺藤摸瓜扫描其他历史会话

### 2. 识别问题并裁决范围

从信息源中找出候选问题：报错、低效调用、文档误导、功能缺口、API 意外行为。

- **只有 1 个问题**：直接进入收集
- **≥2 个独立问题**：列出编号清单（每项一行：类别猜测 + 一句话描述），请用户勾选要收集哪些，再继续

**一问题一报告**。报告的消费端是人，按类别和责任方分诊排期；一份报告混装多个问题就没法归类了。

### 3. 收集证据（每个问题）

- 命令行原文（完整参数）
- 关键输出/报错摘录——截关键片段，不要整屏粘贴
- `yunxiao --version` 输出（只读命令，可以跑；跑不通就记 `unavailable`）
- 会话工作目录、大致时间

**不要重跑出问题的命令来"复现"**：会话里已有的证据足够写报告，重跑可能有副作用，也浪费时间。

### 4. 归类与归因

每个问题**恰好一个主类别 + 一个疑似责任方**（可附次要类别），并在归因说明里写清依据。拿不准就选最像的、把不确定的原因写出来——"疑似"就是本技能的精度承诺，不要为了确定感硬猜。

类别：

| 值 | 含义 | 判断标志 |
|---|---|---|
| `bug` | 命令行为错误或失败，需要改 CLI 代码才能修 | 崩溃、退出码非 0、输出坏掉、错误信息误导 |
| `inefficiency` | 结果对但路径差 | 多余的重复调用、缺缓存、分页笨拙、有更直接的命令没用上 |
| `skill-doc` | 技能文档误导或缺失导致用错 | 按 SKILL.md / 命令文档操作仍然出错或绕路 |
| `missing-feature` | 想做的事没有对应命令/参数 | 用户目标无命令可达 |
| `api-surprise` | 云效 OpenAPI 行为与文档不符或未文档化，CLI 只是如实暴露 | API 返回与官方文档矛盾、未记载的隐含限制 |

疑似责任方：

| 值 | 含义 |
|---|---|
| `cli` | CLI 代码（参数处理、输出、错误处理） |
| `skill-doc` | 技能文档内容 |
| `upstream-api` | 云效 OpenAPI 本身 |
| `usage` | 用法错了（文档没错、CLI 也没错） |

### 5. 写报告

复制 `assets/report-template.md` 填写。正文语言跟随当前会话的语言。

目标路径：

- **用户指定了路径/目录**：按用户指定的写
- **未指定**：`${TMPDIR:-/tmp}/yunxiao-feedback/YYYYMMDD-HHMM-<slug>.md`，slug 用短横线英文概括问题（如 `workitems-table-panic`）
- 同名冲突时追加 `-2`、`-3`，**不要覆盖已有报告**

反馈是随手记的东西，默认不进任何仓库或工作目录；想留存到特定位置是用户的决定，用指定路径表达。

### 6. 收尾

明确告知用户每个报告文件的完整路径，并提醒：默认临时目录重启即清空，需要留存的报告请及时转移（或用指定路径重新收集）。

## 边界

- 只产出报告文件——不改代码、不开 issue、不改技能文档、不做汇总收割
- 不主动扫描历史会话，只处理当前会话或用户指定的转录文件
- 报告基于已有证据，不复现、不修复、不建议修复方案（归因到"疑似责任方"为止）
